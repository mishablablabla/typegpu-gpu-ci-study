## 7. Like-for-like runs with adapter features hidden (`HIDE_FEATURES`)

SwiftShader lacks six adapter features that Metal has (`atomic-vec2u-min-max`, `dual-source-blending`, `primitive-index`, `shader-f16`, `texture-formats-tier1`, `texture-formats-tier2`; Lavapipe has the first four, not the tier features). Only `shader-f16` is used by examples
(`algorithms/mnist-inference`, `image-processing/monocular-light-injection`, `tests/log-test`; all three request it as *optional* and TypeGPU logs `[webgpu-feature-missing]` and falls back). Variant runs hide the six features:

* `runs/metal-hideSSfeatures-run1` (all 97 x 2): 87 ran-clean + 10 needs-unavailable-API, same as the default run.
* `runs/lavapipe-arm64-hideSSfeatures-subset-run1` (the two examples whose WGSL differs between backends: mnist-inference, log-test).
* `derived/variants/RESULTS.md` = Metal(hidden) vs SwiftShader for all examples; `derived/variants/compare-hide3.json` = the three backends for the two f16-sensitive examples.

Result: with f16 hidden, **generated WGSL is identical on all three backends for all 87 examples that run** (without hiding it differs for mnist-inference and log-test only), `tests/log-test` is bit-identical on all three at both checkpoints (the 3 f16-only log lines disappear on SwiftShader by default), and `algorithms/mnist-inference` logits differ by <= 4.6e-4 relative (no element beyond 1e-3 x max(1,|v|)); the other examples do not change class or severity materially (cp3 Metal(hidden)~SwiftShader: 13 identical / 17 tiny / 25 small / 17 moderate / 8 large, vs 13 / 17 / 27 / 17 / 8 default).
